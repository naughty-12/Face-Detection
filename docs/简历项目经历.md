### 为什么"不做自建模型"反而是加分句

> "**我决定不自建检测模型**。人脸检测是成熟任务，自建等于把成本花在重复劳动上；
> 我的取舍是把预算集中在**管线工程与稳定性**上 —— 那是这个产品真正的差异化，
> 也是成熟方案覆盖不到的部分。"

这句话把"用现成模型"从劣势变成了**产品判断**，同时顺势划清了能力边界 —— 决策者叙事的标准动作。

> **角色：项目主导 / 决策者**（技术选型、方案取舍、指标口径与验收标准）

> - **验收标准决策**：要求"未实测的数字不得进文档、所有指标必须标注口径"；主导导出精度**判据从张量误差改为检测质量**（前者会把任何 FP16 模型误判为失败）；据此**否决**了两项当时看起来"已完成"的结论。
> - **成本与风险决策**：实测定位训练显存超额分配（峰值 6.18 GiB > 6 GB 上限、吞吐骤降）后**下调 batch 8 → 6**；**否决**把通用增强管线接入训练（与既有内置增强重叠、收益未经验证），改为先做小规模验证再投入。

> 第二条"判据改为检测质量"是本稿**最值钱的一条** —— 它是纯决策，不靠写代码，且面试官一听就知道你真的在把关。

### 3.4 正式版（「项目描述 + 技术栈 + 技术特点」结构）

> 保持你原来的三段式结构，**保留 Vibe Coding 定位**，事实已按仓库现状校正。
> 旧稿逐条审计见第十一节（**其中 5 处与仓库文档直接矛盾，必须改**）。

**项目描述**
> 项目采用 **Vibe Coding** 范式开发：我担任**决策者**，负责任务拆解、技术选型、方案取舍与结果验收，实现由 AI 辅助完成。产品基于 YOLOv8n-face + Ultralytics 构建实时人脸检测系统，覆盖摄像头 / 视频 / 图片 / 文件夹批量四种输入源，并桥接 VTube Studio 驱动 Live2D 虚拟形象；另导出 ONNX 以支持免装 PyTorch 的跨平台部署（本机 onnxruntime 无 CUDA provider，实际推理以 PyTorch/CUDA 为主路径）。

**技术栈**
> PyTorch + Ultralytics (YOLOv8n) + OpenCV + ONNX / ONNX Runtime + MediaPipe + PyQt5 + WebSocket + TensorBoard
> *（Albumentations 仅用于增强效果可视化、未接入训练 —— 这是一个已记录的决策，写进技术栈前先想好怎么答）*

**技术特点介绍**

> - **数据处理与标注清洗**：解析 WIDER Face 标注（含 `num_faces=0` 假框行等边界情况）并转为 YOLO 格式；训练增强交由 Ultralytics 内置完成（Mosaic / HSV / 翻转 / 平移 / 缩放），**未另接第三方增强管线** —— 理由是它与内置项大面积重叠且缺 Mosaic，接进去是负收益。
> - **两阶段迭代训练**：v1 训练 100 轮打底，v2 加载 v1 权重低学习率精调 30 轮；启用 AMP 混合精度；**实测显存峰值后把 batch 由 8 下调为 6**（batch=8 峰值保留 6.18 GiB，已超 6 GB 物理上限，吞吐从 5.8 掉到 1.7 it/s）。
> - **多维评估与口径管理**：在全部 3,226 张验证图上测 mAP 与 P-R 曲线；按人脸尺寸分 **Tiny / Small / Medium / Large 四档统计召回**，据此定位瓶颈 —— **72.5% 的标注人脸小于 32 px、召回仅 0.493，而 ≥32 px 人脸召回 0.916**；TOP20 漏检/误检汇总可视化。官方 Easy/Medium/Hard 分项因依赖包在本机无法安装而未取得，**一律报 `null`，不用 mAP50 冒充**。
> - **VTube Studio 面部捕捉**：YOLO 检测人脸框 → **外扩 1.45 倍裁剪 ROI** → MediaPipe FaceLandmarker 提取 **478 个关键点与 52 维表情系数** → 多级滤波去抖（EMA + 中值 + 丢失保持 + 换人重置）→ WebSocket 实时注入 VTS（**30 FPS 注入、断线 10 秒自动重连**；VTS 未启动时检测与调试窗口照常运行）。
> - **分步可复现流程**：数据集手动下载 → 标注质检与转换 → TensorBoard 监控训练 → 评估分析 → ONNX 导出并按**检测质量（mAP）而非张量误差**校验（FP16 相对 PyTorch 的 mAP50 差 −0.0002）→ 摄像头实时演示。各步骤为独立命令，**未做一键串联**。

> **最后一条是本版最值钱的诚实句**：把旧稿的"一条命令跑通全流程"改成"各步骤独立命令"，
> 换来的是**你不用在现场解释为什么跑不起来**。想真的做成一键，成本很低（一个 `argparse` 入口串起
> 7 个子命令），做完再把这句话改回去即可 —— 那时它是真的。

## 四、备用版：算法岗 / 被追问模型时展开

> - 全链路：WIDER Face 数据管线（12,880 / 3,226）→ YOLOv8n-face 微调（100 + 30 epoch）→ 评估与误差分析 → ONNX FP16 导出（5.88 MiB，mAP 与 PyTorch 差 ±0.0002）→ 桌面应用集成；**负责口径定义与结果验收**。
> - 含前后处理的单帧检测中位 **10.3 ms / 97 FPS**（PyTorch/CUDA），桥接端 12.5 ms，端到端约 16 ms/帧。
> - 指标标注口径：全验证集 COCO 式 mAP50 **0.664** / P 0.846；按尺寸分层定位瓶颈（72.5% 标注人脸 <32 px、召回 0.493；**≥32 px 召回 0.916**）；发现单次计时噪声达 4.8–18.8 ms 后，要求基线改为报告中位数 / p95 / 样本量。
