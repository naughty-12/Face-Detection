# 架构说明

> 本文描述**当前实现**的架构。历史设计文档（含已废弃的"外六内一 / 六人分工"表述）在
> [`docs/archive/`](archive/README.md)。
>
> 本项目由**一人独立完成**，因此本文按**功能职责**划分模块，不涉及任何人员分工。

---

## 一、三条设计原则

**1. 代码 / 数据 / 产出三者分离**

`src/`、`data/`、`artifacts/` 互不混放。脚本不写进数据目录，权重与图表不写进源码目录。
理由是这三类东西的生命周期完全不同：代码进版本库，数据体积大且可重新获取，产出可随时重建。

**2. 路径只有一处定义**

所有路径来自 [`src/paths.py`](../src/paths.py)。任何其他模块都**不得**用 `__file__` 自行推算项目根。

这不只是风格问题。项目早期每个脚本写 `os.path.dirname(os.path.dirname(__file__))` 来求项目根，
在扁平目录下成立；一旦脚本进入子包（如 `src/deploy/detect.py`），同一表达式会算出 `src/` 而不是
项目根，于是所有数据与权重路径同时失效。把根目录解析收敛到唯一一处，使得**脚本可以自由移动**。

**3. 依赖单向**

```
deploy  →  eval  →  train  →  data  →  paths
```

反向依赖一律不允许：数据管线不知道训练代码的存在，训练不依赖部署代码，`paths.py` 不依赖任何模块。
好处是可以单独测试或重跑任一环节，而不必把整条链路拖起来。

## 二、模块划分

| 模块 | 目录 | 职责 | 关键文件 |
|:---|:---|:---|:---|
| **路径基础** | `src/paths.py` | 全项目唯一的路径来源 | — |
| **数据管线** | `src/data/` | 数据集准备、标注质检、YOLO 格式转换、train/val 划分、数据集封装、增强管线 | `convert.py`、`loader.py` |
| **训练** | `src/train/` | 超参管理、v1 基线训练、v2 微调、断点续训、模型诊断 | `train.py`、`resume.py` |
| **评估** | `src/eval/` | mAP 评估、P-R 曲线、困难样本与错误分布分析 | `evaluate.py`、`analyze_errors.py` |
| **部署** | `src/deploy/` | 实时检测、ONNX 导出、性能基准 | `detect.py`、`export_onnx.py` |
| **应用** | `apps/vtube_bridge/` | VTube Studio 表情驱动 | `vtube_studio_bridge.py` |
| **配置** | `configs/model.yaml` | 训练超参与模型选型 | — |
| **产出** | `artifacts/` | 权重、训练曲线、评估图表、日志 | — |

**`src/` 与 `apps/` 的区别**：`src/` 是可被导入的库代码，脚本通过 `python -m src.<pkg>.<module>` 运行；
`apps/` 是可独立运行的完整应用 —— 它自带第三方依赖（MediaPipe 模型文件）与 GUI，对外只需要一个入口。

## 三、数据流

```
WIDER Face 原始数据（data/raw/、data/annotations/）
        │
        ▼  src/data/convert.py      标注 → YOLO 归一化 labels/
        │                            （与 images/ 平行的同构目录）
        ▼  src/data/split.py        生成 train_list.txt / val_list.txt
        │                            ↑ 评估与 ONNX 精度验证的前置产物
        ▼  train.py 动态生成 data/annotations/widerface.yaml
        │                            （path: data/raw，相对项目根）
        ▼  src/train/train.py       ultralytics 直接读 images/ ↔ labels/
        │                            ★ 训练并不需要 train_list.txt
        ▼  artifacts/checkpoints/best_model_v1.pt
        │  src/train/train.py（v2）  从 v1 权重再跑 30 epoch
        ▼  artifacts/checkpoints/best_model_v2.pt
        │
        ├─▶ src/eval/*                 mAP、P-R、困难样本 → artifacts/reports/
        └─▶ src/deploy/export_onnx.py  → best_model_v2.onnx（FP32 + simplify）
                    │
                    ▼  src/deploy/detect.py      实时检测（摄像头/视频/图片/文件夹）
                    ▼  apps/vtube_bridge/         表情驱动 Live2D
```

**一个容易混淆的点**：`train_list.txt` / `val_list.txt` 与训练的**数据加载**无关 ——
ultralytics 依据 `images/` 与 `labels/` 的同构目录直接扫描。这两个清单文件只被**评估**与
**ONNX 精度验证**使用，所以它们缺失时训练照常，但评估环节会静默降级。

## 四、运行时架构

### 管线一：检测与推理

```
输入（摄像头索引 / 视频 / 图片 / 文件夹）
        │  src/deploy/detect.py 按输入类型自动分派
        ▼
ultralytics YOLO (best_model_v2.pt，可换 .onnx)
        │  内部完成 letterbox 预处理 → 网络前向 → 解码 → NMS
        ▼
绘制人脸框 + 置信度 + 30 帧滑窗平均 FPS
        │
        ├─ 摄像头/视频 → 实时窗口（q 退出，s 截图）
        └─ 图片/文件夹 → 可选 --save 落盘（--no-show 关闭结果窗口）
```

### 管线二：VTube Studio 表情驱动

```
摄像头帧
   │
   ▼ ① YOLOv8n-face 检测人脸框                                  ~6 ms
   ▼ ② FaceBoxFilter   EMA(α=0.55) + 中值滤波(window=5)
   │                   + hold 3 帧 + 新人脸重置(reset_distance)
   ▼ ③ 裁剪 ROI（外扩 1.45 倍）                      ★ 先检测再裁剪
   ▼ ④ MediaPipe FaceLandmarker                                 ~8 ms
   │      478 关键点 + 52 ARKit blendshape
   │      + facial transformation matrix → SVD → 头部欧拉角
   │      + 虹膜关键点归一化 → 视线方向 (-1, 1)
   ▼ ⑤ ParameterFilter  表情(α=0.45) / 头部(α=0.35) / 眼球(α=0.35) 三通道独立 EMA
   ▼ ⑥ TrackingCalibrationManager  按 VTS 返回的 min/max 裁剪
   │                                + 源范围采集映射 + 一键回中 + JSON 持久化
   ▼ ⑦ VTubeStudioWorker  daemon 后台线程，30 FPS 注入，断线 10 s 自动重连
VTube Studio → Live2D 形象跟随表情
   （旁路：PyQt5 调试窗口实时显示 16 个参数、摄像头预览、点击选脸）
```

## 五、关键设计决策

| 决策 | 理由 | 代价 |
|:---|:---|:---|
| 路径统一由 `src/paths.py` 提供 | 脚本可自由移动，不再依赖自身目录深度 | 少量间接层，需记住常量名 |
| 脚本以 `python -m src.<pkg>.<module>` 运行 | 导入关系显式，CWD 固定为项目根 | 不能再直接 `python path/to/script.py` |
| `data/annotations/widerface.yaml` 位置与 `path: data/raw` 相对形式保持不变 | ultralytics 对相对 `path` 的解析行为未经实测，改动风险高收益低 | 生成物混在数据目录里 |
| 桥接保持为独立应用（`apps/`），不并入 `src/` | 它自带 MediaPipe 模型与 GUI，耦合低、可单独交付 | 路径解析方式与主项目不统一 |
| 先 YOLO 检测、再裁剪 ROI 送关键点模型 | 人脸在输入中占比大幅提升，关键点与表情系数更准 | 多一次裁剪开销，且外扩比例需调（1.45 为经验值） |
| 人脸框三级滤波（EMA + 中值 + hold） | 抗抖动、抗单帧跳变、短暂遮挡不闪烁 | 引入可控延迟，需与响应速度权衡 |
| VTS 发送放在 daemon 线程 | 网络 I/O 不阻塞推理主循环 | 需处理线程间状态同步与断线重连 |
| ONNX 静态 shape 导出（`dynamic=False`） | 部署固定 640×640，静态图可获更充分优化 | 无法变分辨率推理 |

## 六、已知耦合与技术债

| 项 | 说明 | 影响 |
|:---|:---|:---|
| **WIDER 标注解析有 4 份重复实现** | `convert.py`、`qc.py`、`split.py`、`loader.py` 各自实现了一遍标注解析 | 边界情况（如 `num_faces=0` 却带全零假框）只在 `convert.py` 里被处理，其余三份都漏；应抽取到单一模块 |
| 训练增强与 `augment.py` 不一致 | 训练用 ultralytics 内置增强，`src/data/augment.py` 的 Albumentations 管线未接入 | 该模块目前只服务于 `vis_aug.py` 的可视化，属半成品 |
| `loader.py` 在函数内 import `augment` | 避免 albumentations 成为硬依赖 | 隐藏了依赖关系，静态检查工具不易发现 |
| `apps/vtube_bridge` 不依赖 `src/` | 低耦合，可单独交付 | 模型路径解析自成一套，主项目移动目录时需同步核对 |
| 无单元测试 | `tests/` 为空；`check_model.py` 只打印不宣告失败 | 重构缺乏安全网，本次目录重组只能靠静态断言与实跑验证 |

## 七、扩展点

- **模型替换**：`configs/model.yaml` 的 `model_name` 与 `src/deploy/detect.py` 的 `DEFAULT_MODEL` 两处。
- **推理后端**：`detect.py` 通过 ultralytics 加载，换成 `.onnx` 只需改 `--model`。
- **表情维度扩展**：桥接当前精选 6 个表情维度，MediaPipe 已提供全部 52 个 ARKit blendshape。
- **新增数据源**：在 `src/data/` 下加转换脚本，产出 YOLO 格式 labels 即可，训练侧无需改动。
- **测试接入**：`tests/` 已预留，纯函数（坐标转换、`FaceBoxFilter` 的 hold/中值行为）最适合优先覆盖。
