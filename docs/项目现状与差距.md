## 八、优化方向：定向增强（"把 Albumentations 真正接入训练"）

> **状态：已评估，暂不采纳。已采用方案 B**（该模块定位为可视化工具，见 `src/data/augment.py`
> 头部说明）。本节记录"如果要做，重点在哪、为什么现在不做"，避免以后重复评估。

### 8.1 为什么"把现有管线接进训练"本身没有价值

`src/data/augment.py` 的全部变换，ultralytics 内置增强**已经覆盖**：

| 该模块 | ultralytics 对应 |
|:---|:---|
| `HorizontalFlip(p=0.5)` | `fliplr=0.5` |
| `RandomBrightnessContrast` / `HueSaturationValue` | `hsv_h` / `hsv_s` / `hsv_v` |
| `Blur(blur_limit=3/5)` | `auto_augment='randaugment'`（RandAugment 含各类模糊） |
| `CoarseDropout`（即 Cutout） | `erasing=0.4` |
| `Resize(640,640)` | letterbox 到 `imgsz` |
| — | **`mosaic=1.0`（该模块没有）** |

所以两种接法都是负收益：**替换**会丢掉 Mosaic（检测任务最有价值的增强）；**叠加**会让翻转与
HSV 施加两次、概率失准。

> 附带结论：设计文档承诺的"后 50 epoch 加入 Cutout/模糊"**其实早已被 ultralytics 的默认值满足**
> （`erasing` 即 Cutout，`randaugment` 含模糊），只是不由该模块实现，因此看起来像"没做"。

> **补充证据（做出本决策后修复时发现）**：该模块的 `CoarseDropout` 用的是 Albumentations **1.x
> 的参数名**（`max_holes` / `max_height` / `max_width`），而项目安装的是 **2.0.8** —— 这三个参数被
> **静默忽略**，实际生效的是默认值 `num_holes_range=(1,2)`、`hole_height_range=(0.1,0.2)`，
> 即"1~2 个 10~20% 大小的洞"，而非预期的"最多 8 个 ≤32px 洞"。已修为 2.x API 并把
> `requirements.txt` 收紧到 `albumentations>=2.0.0`。
>
> 这是又一个"配置被静默忽略"的实例，也进一步支持 8.3 的第 2 条：**在把它接进训练之前，得先确认
> 它在当前依赖版本下真的按预期工作** —— 而它连这一关都没过。

### 8.2 如果要做，重点是什么

真正的收益不在"多几种标准增强"，而在 ultralytics **做不到**的两件事 —— 它们恰好各自对应一个
**已实测的短板**：

| 重点 | 做法 | 对应的实测依据 |
|:---|:---|:---|
| **① 属性感知增强** | WIDER 标注为每张脸附带 `blur / expression / illumination / occlusion / pose` 属性。按属性定向增强：标注"暗光"的样本加大亮度扰动、标注"遮挡"的样本加 CoarseDropout、标注"侧脸"的样本加小角度旋转。**ultralytics 看不到这些字段**（当前解析时被跳过，见 G14） | 汇总召回 0.610，而 ≥32px 人脸的召回已达 **0.916** —— 剩下的失误集中在困难子集，而困难程度是**标注里就有**的 |
| **② 小脸放大裁剪** | 随机裁出含小人脸的区域并放大到 640，让 <32px 的脸在训练时"变大"。这是提升小脸召回最直接的数据侧手段 | **72.5% 的 GT 人脸 <32px，其召回仅 0.493**（尺寸分层实测） |

配套必须解决的问题 —— 这才是"接入"的真实成本：

1. **去重**：关闭 ultralytics 中与本管线重叠的变换（`fliplr` / `hsv_*` / `erasing` / `auto_augment`），
   否则双重施加；
2. **补 Mosaic**：Albumentations 无内置 Mosaic，若走替换路线必须自行实现；
3. **打通数据层**：ultralytics 的 Dataset / Transform 层需要自定义 Dataset + trainer 钩子，
   不是换一个 `Compose` 就能接上。

### 8.3 为什么现在不做

1. **顺序不对**：应先确定"加哪种定向增强"（8.2 的两条），再决定**载体**。载体有 Albumentations 与
   ultralytics 自定义 Dataset 两个候选，选择取决于要做的事 —— 不是反过来先接入一个通用管线。
2. **收益尚未被证明**：8.2 的两条目前都是**假设**，需要先做小规模前置实验（例如只做"小脸放大裁剪"
   跑 10 epoch，对比 <32px 召回）。在拿到这个实验结论前接入通用管线，只是增加复杂度。
3. **瓶颈已定位到数据/分辨率侧**：尺寸分层指出核心问题是 <32px 的脸在 640 输入下不足 10px。
   提高推理/训练分辨率可能是**成本更低**的同一方向解法，应当一并比较。
4. **风险**：接入会改变训练数据分布，使既有 `best_model_v2.pt` 失去可比性；且现有 56 个测试
   **不覆盖训练的数据路径**（见 8.4）。

### 8.4 已采用的方案（方案 B）与其配套

- `src/data/augment.py` 保留，**文件头写明定位为可视化工具、不参与训练及原因**；
- `src/data/vis_aug.py` 继续用它渲染增强后的批次供人工检查 —— 这正是将来设计 8.2 定向增强时的
  验证手段；
- **文档同步**：README、架构说明、CHANGELOG 一致表述，消除"文档写了未实现"的落差。

> 若将来启动 8.2：**第一步不是改 `augment.py`，而是补训练数据路径的测试**（自定义 Dataset 的
> 变换正确性、框与图同步性），否则改错不会有人发现。
